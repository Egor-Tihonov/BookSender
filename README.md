# BookSender

Telegram бот на Go. Видит в чате файлы epub, fb2, mobi, копит их 5 минут
с первой книги и отправляет накопленное одним письмом на почту.
Работает на Koyeb (бесплатный тариф), сообщения получает вебхуком.

## Как работает

1. Telegram присылает вебхук на `POST /webhook` при каждом сообщении в чате.
2. Бот проверяет документ: расширение epub, fb2 или mobi и размер не больше
   `MAX_FILE_MB`. Слишком большой файл пропускается с уведомлением в чат.
3. Книга попадает в батч по `file_unique_id`, дубли отбрасываются.
   Скачивание на диск начинается сразу, параллельно с приёмом новых вебхуков.
4. При первой книге запускается таймер `BATCH_WAIT`. Новые книги таймер
   не сбрасывают. Если общий вес батча превысит `MAX_BATCH_MB`, текущий
   батч уходит досрочно, а новая книга открывает следующий.
5. По таймеру батч режется на письма не больше `MAX_MAIL_MB` книг в каждом
   и уходит по SMTP. На письмо 3 попытки с паузой 10 секунд.
6. Файлы отправленных книг удаляются. Неотправленные возвращаются в батч
   и уходят со следующей отправкой, максимум 3 круга, потом удаляются
   и в чат уходит уведомление.
7. При старте временная папка очищается целиком.

`GET /` отвечает `ok`, это проверка живости для Koyeb.

## Файлы

| Файл                      | За что отвечает                                              |
| ------------------------- | ------------------------------------------------------------ |
| main.go                   | точка входа, HTTP сервер, обработчик вебхука                 |
| internal/config.go        | переменные окружения, локально из `.env`                     |
| internal/telegram.go      | Telegram API: разбор апдейта, getFile, скачивание, сообщения |
| internal/batch.go         | батч: дубли, таймер, лимит веса, повторы неотправленных      |
| internal/mailer.go        | разбивка по письмам, MIME, SMTP с ретраями                   |
| Dockerfile                | двухэтапная сборка, образ на alpine                          |
| .github/workflows/ci.yml  | lint и test на pull request, ручной деплой на Koyeb          |

## Переменные окружения

| Переменная      | По умолчанию | Что это                                        |
| --------------- | ------------ | ---------------------------------------------- |
| TELEGRAM_TOKEN  |              | токен бота от BotFather                        |
| PORT            | 8000         | порт HTTP сервера                              |
| SMTP_HOST       |              | например smtp.gmail.com или smtp.yandex.ru     |
| SMTP_PORT       | 587          | 587 для STARTTLS, 465 для TLS                  |
| SMTP_USER       |              | адрес ящика отправителя                        |
| SMTP_PASS       |              | пароль приложения, не пароль от аккаунта       |
| SMTP_FROM       |              | адрес в поле From, обычно тот же, что SMTP_USER |
| MAIL_TO         |              | куда слать книги                               |
| BATCH_WAIT      | 5m           | окно батча от первой книги                     |
| MAX_FILE_MB     | 20           | файл больше пропускается                       |
| MAX_MAIL_MB     | 18           | книг в одном письме, с base64 это около 25 МБ  |
| MAX_BATCH_MB    | 50           | вес батча, при превышении отправка досрочно    |
| TMP_DIR         | tmp          | папка для скачанных книг                       |
| LOG_LEVEL       |              | `debug` включает подробные логи                |

Локально переменные читаются из файла `.env` в корне проекта, он в `.gitignore`.
На Koyeb задаются в настройках сервиса, токен и пароль как Secret.

## Запуск локально

```bash
go run .
```

Публичного адреса для вебхука на ПК нет, поэтому локально удобно проверять
через тестовый POST на `/webhook` с JSON апдейта Telegram.

## Деплой

Koyeb собирает Docker образ сам из репозитория по ветке `main`.
Вебхук регистрируется один раз:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://<сервис>.koyeb.app/webhook"
```

### CI

- На pull request бегут `lint` (gofmt, go vet) и `test` (go test -race).
- Ветка `main` защищена: мерж только через pull request с зелёными проверками.
- Деплой ручной: Actions → ci → Run workflow, ветка `main`. Джоба ставит
  Koyeb CLI и делает `koyeb services redeploy`, переменные сервиса не трогает.

Нужны в Settings → Secrets and variables → Actions:

| Тип      | Имя           | Значение                 |
| -------- | ------------- | ------------------------ |
| Secret   | KOYEB_TOKEN   | API ключ Koyeb           |
| Variable | KOYEB_APP     | имя приложения в Koyeb   |
| Variable | KOYEB_SERVICE | имя сервиса в Koyeb      |

## Ограничения

- Bot API не отдаёт боту сообщения других ботов: файлы, присланные другим
  ботом, нужно пересылать в чат вручную.
- Состояние живёт в памяти: перезапуск во время 5-минутного окна теряет
  текущий батч, книги придётся прислать заново.
- Bot API скачивает файлы до 20 МБ, поэтому `MAX_FILE_MB` выше ставить нет смысла.
